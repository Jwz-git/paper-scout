# 智能体流程与停止规则

状态：设计草案。模型提出计划、提取和综合；程序负责执行工具、计数、状态流转与证据关联。所有阈值为开发建议，需通过样本评估调整。

## 阶段

| 阶段 | 输入与操作 | 输出及完成条件 |
| --- | --- | --- |
| 理解 | 从问题和范围提取主题、子问题和关注维度 | 结构化任务；缺少必要对象且无法合理推断时转 `needs_input`，说明缺项 |
| 规划 | 生成覆盖子问题的查询、同义词和筛选条件 | 记录查询计划；每次查询映射到至少一个子问题 |
| 检索 | 按计划调用已配置源，规范化并去重 | 记录查询、结果和失败；来源失败与无结果分开 |
| 解析 | 按相关性选取论文，读取摘要和允许访问的文本型全文 | 记录实际读取范围、原文片段、字段及缺失原因 |
| 评估 | 计算子问题覆盖和字段完整率，汇总来源及解析失败 | 得到缺口清单和是否继续；记录规则依据 |
| 补充检索 | 针对未覆盖子问题或缺失方法，生成与已有查询不同的关键词 | 开始下一轮；重复查询或达到执行限制则停止 |
| 综合与报告 | 汇总有证据的字段与可比较条件 | 输出报告、参考文献、局限和终止原因 |

所有外部调用在执行限制允许时发起，重试也计入用量。每轮和每个阶段结束时保存结果，便于查看过程；任务中断不自动重复费用调用。

## 暂停、补充和继续

1. 执行中的用户请求暂停后标记 `pause_requested`；当前外部请求完成或超时后保存已完成结果和检查点，进入 `paused`，期间不发起下一次外部请求。界面显示“正在暂停”直至真正暂停。
2. 在 `paused` 或系统主动进入的 `needs_input` 状态，用户可追加文本；补充信息与原任务分别保存。继续前由用户显式触发，进入队列。
3. worker 先判断补充信息是否影响检索范围、子问题、筛选或报告要求；更新计划及相关性判断，保留历史论文、来源和证据，排除不再适用的结果。重新执行必要的后续阶段，记录调整原因。
4. 继续使用同一运行与累计调用数；暂停等待时间不计入运行时限，实际执行时间跨暂停累加。达到既有限制时按现有停止规则处理。

当前建议采用对话式输入配过程记录的界面，用户可看到系统提问、补充信息和阶段变化；布局不影响以上运行语义，后续可调整。

## 充分性：可检查的启发式

建议每个运行先得到用户关注的子问题；规划不得依赖“模型认为充分”作为唯一依据。默认候选阈值：至少 6 篇纳入论文；每个子问题至少 2 篇经筛选相关论文；各论文在用户关注字段中，有证据的非空字段比例平均至少 60%。分母只包含该任务适用的关注字段；没有适用字段时不计算该比例，并提示任务目标需调整。相关性可由模型或人工判断，其判断本身存在误差。

同时必须满足：每个关键论文事实有可定位证据，尚未解决的关键矛盾和缺口均被披露。这些规则仅决定是否达到系统的操作性停止条件，不能证明文献覆盖全面或结论正确。

示例：有 8 篇论文但“低资源场景”只有 1 篇相关文献时，数量满足、覆盖不满足；优先补充该子问题的查询。若只找到了摘要，方法字段可用摘要证据，但未提及的实验数据应标缺失；继续搜索不保证一定能获得全文。

若无新查询、两轮结果均无新增可用论文、来源不可用或达到执行限制，则停止继续检索，记录相应原因。按已有证据可形成报告时标记 `partial`；资料不足以形成可核查报告则 `failed`。若原定目标满足且报告已生成，标记 `completed`。

## 默认执行限制建议

| 限额 | 建议值 | 说明 |
| --- | --- | --- |
| 检索轮次 | 3 | 包含第一轮 |
| 每轮查询 | 3 | 不同来源各算一次请求 |
| 纳入论文 | 12 | 筛选与成本之间的初始折中 |
| 全文解析 | 6 篇 | 可配置；其余仍可使用摘要 |
| 模型请求 | 30 次 | 包含重试，预留 2 次给报告生成 |
| 外部检索／下载请求 | 60 次 | 包含重试及重定向 |
| 实际执行时间 | 15 分钟 | 不含暂停等待；为报告阶段预留时间，每次调用不超过剩余时间 |

默认值不是质量保证。记录调用次数和运行时间；供应商提供 token 或费用数据时记录和展示，未知时显示未知，不当作零。首期不提供金额预算、费用上限或超额拦截功能。

## 失败和证据

只针对限流、超时等可识别的暂时错误做有限重试，遵守服务规则并计入调用统计；无权限、错误配置或格式错误直接记录。结构化模型输出无法解析时记录失败，不能补造结果。报告中的引用 ID 和文本位置可由程序检查；语义是否支持结论需抽样人工核查。模型自评分不是正确率。

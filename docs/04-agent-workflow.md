# 对话 agent 与执行规则

状态：已实现单一对话 agent、阅读子 agent、执行上限与收尾、执行中插话、停止和上下文压缩，并有离线定向测试。真实模型（包括所用网关的并发与 JSON 输出稳定性）、arXiv 网络和科研语义质量尚未验收。上限是固定的操作性数值，不是质量保证。

## 结构

每个对话由同一个 agent 接收全部消息。没有单独的对话路由，也没有固定阶段流水线：是直接回答、先澄清、检索、精读、写报告还是回答追问，由 agent 按对话和工作区决定。

- **一条消息一轮**：每条用户消息开启一轮工作，直到 agent 回复、失败或被停止为止。执行中收到的新消息并入正在进行的这一轮（见“执行中插话”）。
- **对话工作区**：每个对话有一个 `agent=true` 的 Run，作为跨轮次的工作区，保存候选论文、读过的原文与范围、证据、纳入判断和报告。后续轮次在同一工作区上继续，不重复下载已取得的原文。
- **分工**：模型负责计划、选择工具、概括发现和写作。代码负责执行工具、计数、执行上限、引文定位与核对、状态保存和上下文压缩。模型输出不能执行任意代码、命令或 URL；论文和检索结果中的指令一律作为数据。

## 步骤协议

模型每一步只输出一个 JSON 对象 `{"thought": "...", "actions": [...]}`，最多 6 个动作，按顺序执行，结果在下一条消息里返回。入口处由 pydantic 校验一次：主 agent 的 `reply` 和阅读子 agent 的 `done` 只能放在最后。可以同一步先更新 `todo` 或保存 `report` 再 `reply`；前面的工具失败时不执行回复，将结果交回模型改正。需要先看到工具结果才能写回复时，应在下一步回复。

不使用供应商的原生工具调用，是因为用户所用网关目前只验证过 JSON 输出，原生工具调用能力尚未验证（见 [决策记录](<06-decisions.md>)）。

| 工具 | 作用 | 代码侧约束 |
| --- | --- | --- |
| `search` | 检索 arXiv，结果进入候选 | 每条 1–30 条结果；年份用参数传入；同一层括号内混用 AND 与 OR 时不发请求，退回模型加括号；“只用已有资料”模式下拒绝 |
| `read` | 读摘要，或读全文指定页（每次最多 4 页） | 首次读全文时下载 PDF 并计数；一步返回的原文有总量上限，放不下的页不读、不记为已读 |
| `find` | 在已取得的全文中查找词句 | 最多 8 处命中，每处返回前后约 400 字符，并只把这些窗口记为已读 |
| `note` | 记录字段发现和实验结果 | 引文逐条核对，见“证据规则”；全部引文都未通过时这次 note 不保存 |
| `decide` | 纳入或排除论文并写明理由 | 以最后一次判断为准 |
| `workspace` | 查看工作区概况或某篇论文的已读范围、发现和证据 | 只读 |
| `todo` | 更新计划清单 | 显示在界面上；上下文压缩时保留 |
| `delegate` | 把 1–6 篇论文交给阅读子 agent | 见“阅读子 agent” |
| `report` | 写报告：章节、主张及其证据、缺口 | 证据标识必须存在且不属于已排除论文；代码补充未读全文等缺口 |
| `reply` | 回复用户并结束本轮 | 引用的证据标识必须存在，否则错误交回模型改正 |

## 一轮的执行

1. **开场**：给模型当天日期、消息模式、最近对话（最多 20 条、24000 字符）、工作区概况、本条消息和本轮上限。
2. **每步之前**：先并入执行中收到的新消息，再调用模型。
3. **输出无效**：格式或校验错误连同原因交回模型改正。模型输出中出现由系统回传的字段（`results`、`budget`、`notices` 等）时，代码丢弃这些字段再校验，工具结果始终以代码实际执行为准。连续 3 次无效时进入收尾（见下文），终止原因记为“模型连续 3 次输出不符合格式”，工作区资料保留。服务返回的内容过滤或拒绝不当作 JSON 格式错误；所用网关的内容过滤实测对同一篇论文时有时无，因此按暂时错误重试（见“收尾、停止与失败”）。暂时错误（含拒绝）重试后仍失败时，主 agent 本轮失败；阅读子 agent 的模型调用失败（无论是否暂时错误）只结束该子任务并将原因交回主 agent，不丢弃其他子任务的结果，鉴权等全局错误由主 agent 的下一次调用使本轮失败。
4. **执行动作**：工具错误作为结果返回给模型，不中断本轮。程序错误（代码缺陷）立即使本轮失败（`internal_error`），界面只显示错误类别。
5. **预算提示**：剩余步数 ≤3、外部调用 ≤12 或时间 ≤300 秒时，提示模型停止新的检索和精读，整理已有证据。
6. **结束**：`reply` 结束本轮。计划清单还有未完成项、且预算未进入提示区时，第一次 `reply` 退回模型，要求完成这些项或标为 done 并说明原因；每轮只退回一次。达到上限时进入收尾（见下文）。

每个动作执行前更新 `work.activity`，并为思考、工具结果、工具错误、重试、上限和收到的消息写入事件。事件的 `turn_id` 是对应助手消息的标识，`actor` 为 `agent`、`user` 或 `reader:{paper_id}`。界面轮询这些持久化状态显示进度，不是模型 token 流。

## 阅读子 agent

`delegate` 把多篇论文交给阅读子 agent 并行精读，同时最多运行 3 个。

- 每个子 agent 只处理一篇论文，只能 `read`、`find`、`note` 和 `done`，最多 8 步。
- 子 agent 只看到论文信息、全文状态，以及主 agent 给出的背景和要求，看不到对话。
- 子 agent 与主 agent 共用本轮预算；任一方达到上限后，其余子 agent 以 `incomplete` 结束。
- 所有子 agent 结束后，主 agent 才收到汇总：状态（`done`、`incomplete`、`failed`）、总结、实际读取范围和新证据标识。不留下游离任务；停止时随本轮一起取消。

同一轮的模型请求同时最多 1 个：子 agent 的工具执行（下载、读取、记录）并行，模型请求排队，排到后才计数和计时。原因是所用网关在 2–3 个请求同时进行时频繁返回 5xx，单个请求正常（2026-11-08 实测观察，网关的并发限制未经官方确认）。

## 证据规则

- **先读后引**：引文只能来自本轮或之前实际返回给模型的原文范围（摘要、读过的页、`find` 窗口）。没有读过这篇论文时 `note` 直接拒绝。
- **由代码定位**：模型只提供来源标识和逐字摘录。代码在原文中定位并计算字符区间，忽略空白、连字符和 Unicode 兼容形式的差异（PDF 换行与断词）。保存的证据是原文中实际的那一段，数据库再次核对 `content[start:end] == quote`。
- **拒绝的情况**：来源不属于这篇论文、摘录太短（规范化后不足 8 个字符）、原文中找不到、出现多次无法确定位置、位置不在已读范围内。每条被拒的引文都附原因返回，模型可以改正后重新 `note`。
- **缺失明确标记**：有内容的发现必须带引文；缺失的字段写 `missing_reason`，不能带引文。
- **全文获取**：下载超时、网络或 DNS 错误，以及地址检查未通过（取决于当时的 DNS 结果）属于暂时失败，不写入状态，模型可以稍后重试。其他失败（HTTP 错误、超出大小、解析失败或超时等）记为该论文全文不可用，不再重复下载。全文下载每轮最多 10 篇。
- **报告**：主张引用的证据必须存在，且不属于已排除的论文。被引用但尚未判断的论文自动纳入，理由记为“报告引用了这篇论文的证据”。代码为每篇纳入论文补充“尚未阅读”“未读取全文，当前最多基于摘要”或“全文 N 页中完整读过 K 页”（只看过 `find` 片段的页不算读过）的缺口；实验比较和字段覆盖由代码计算，见 [数据与接口](<03-data-and-api.md>)。
- **只用已有资料**：`ask` 模式下拒绝检索和新的全文下载，已保存的摘要与全文仍可阅读和引用。

引文能定位只说明原文确实存在，不说明它支持主张；语义仍需人工抽样核查。模型自评分不是正确率。

## 执行上限

上限按轮计算：每条新消息有一份新的额度；子 agent 共用这一份。对话和工作区的用量只做累计统计，不设终身上限，也不做金额预算。

| 限额 | 当前值 | 说明 |
| --- | --- | --- |
| 主 agent 步数 | 30 | 每次模型决策算一步 |
| 外部调用 | 150 次 | 模型、arXiv、PDF 下载及跳转都计入，重试也计入；请求发出前计数并保存 |
| 执行时间 | 1800 秒 | 单次模型请求最长 180 秒，且不超过剩余时间（最短 1 秒） |
| 全文下载 | 10 篇 | 暂时失败的下载也计入 |
| 同时运行的子 agent | 3 | |
| 每个子 agent 步数 | 8 | |

设置页只读显示这些实际生效值。供应商返回 token 用量时累计显示；任何一次调用没有用量（例如被取消或超时）时，总数显示为未知，不当作零。

## 收尾、停止与失败

- **收尾**：达到步数、调用或时间上限，或主 agent 连续 3 次输出无效后，停止检索、阅读和记录，再给模型最多 2 次调用和 150 秒，只允许输出 `reply`，说明完成了什么、有证据的发现、还缺什么。模型仍未给出有效回复时，由代码按工作区计数生成概况（已保存报告时提示查看）。终止原因记在 `work.stop_reason`，界面显示为“提前结束”。
- **重试**：模型的 `rate_limited`、`timeout`、`network_error`、`server_error` 和拒绝（`refusal`，含内容过滤）最多重试 2 次，间隔 2 秒和 5 秒；arXiv 同类错误由适配器最多尝试 3 次，间隔 5 秒和 10 秒，并遵守请求间隔。每次尝试都计入调用。鉴权、配置和其他 HTTP 错误不重试，主 agent 遇到时本轮失败（子 agent 遇到时见上文“输出无效”）；若本轮已保存报告，失败消息提示查看。
- **停止**：停止会取消正在进行的模型或外部请求。已经计数的调用保留，被取消调用的 token 记为未知；消息显示“已停止。”。worker 继续处理后续消息。
- **重启**：服务重启时，处理中的消息标为中断，不自动重放已发起的付费请求。旧版流水线遗留的未结束运行标为中断并说明原因，资料仍可查看；其中已纳入的论文和已取得的原文带入该对话的工作区。
- **未配置模型**：消息直接失败并提示先配置模型，不再提供无模型的关键词检索。

## 执行中插话

执行中发送的消息不需要先停止。agent 在下一次模型调用前读到这些消息（`new_messages`），并在同一工作区和同一份额度中继续：

- 已开始的工作记录留在原来的助手消息下，标记“后续在下一条回复中继续”；后续工作和最终回复出现在最新消息下方。
- 工作还没开始就收到的多条消息一起交给模型，中间的空回复不显示。
- 消息模式以最新一条为准，例如切换到“只用已有资料”后不再检索。

## 上下文压缩

主 agent 保留最近 6 步原文，步数超过 12 或上下文超过 120000 字符时，把更早的步骤压缩为思考、动作摘要、结果摘要、证据标识和当时收到的新消息，计划清单并入开场。子 agent 分别为 3 步、5 步和 60000 字符。至少保留最后一步原文。

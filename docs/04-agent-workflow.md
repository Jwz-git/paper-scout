# 智能体流程与停止规则

状态：已实现有界筛选、提取、比较、评估与综合原型。模型提出计划、提取和综合；程序负责执行工具、计数、状态流转与证据关联。初始操作性阈值已落入运行快照，仍需真实样本评估，不能当作科研质量保证。

## 阶段

| 阶段 | 输入与操作 | 输出及完成条件 |
| --- | --- | --- |
| 理解 | 从问题和范围提取主题、子问题和关注维度 | 结构化任务；缺少必要对象且无法合理推断时转 `needs_input`，说明缺项 |
| 规划 | 生成覆盖子问题的查询、同义词和筛选条件 | 记录查询计划；每次查询映射到至少一个子问题 |
| 检索 | 按计划调用已配置源，规范化并去重 | 记录查询、结果和失败；来源失败与无结果分开 |
| 解析 | 按相关性选取论文，读取摘要和允许访问的文本型全文 | 记录实际读取范围、原文片段、字段及缺失原因 |
| 评估 | 计算子问题覆盖和字段完整率，汇总来源及解析失败 | 得到缺口清单和是否继续；记录规则依据 |
| 补充检索 | 针对未覆盖子问题或缺失方法，生成与已有查询不同的关键词 | 开始下一轮；重复查询或达到执行限制则停止 |
| 综合与报告 | 汇总有证据的字段与可比较条件 | 输出报告、参考文献、局限和终止原因 |

所有外部调用在执行限制允许时发起，重试也计入用量。每轮和每个阶段结束时保存结果，便于查看过程；任务中断不自动重复费用调用。

## 当前执行路径

`planning → searching → screening → extracting → analyzing → assessing → synthesizing → reporting`。

- 规划输出每条查询对应的子问题。无用户补充时不能在补检中偷偷更换既定子问题。无新查询但有范围补充时，仍筛选/分析已存资料；纯资料问答沿用对话层，不触发研究修订。
- 筛选最多保留12篇候选，每篇保存判断依据；超过容量或未完成筛选的条目明确未审阅。单篇筛选结果缺失或无效时，只把该篇记为未纳入并写入缺口，其他论文的有效结果照常使用。筛选与字段提取只让模型返回来源标识和原文摘录，由代码在本次提供的片段内做唯一精确定位并计算全局字符区间；找不到或多处匹配均失败，不让模型估算位置。先筛选，再把下载额度用于纳入资料；给分析和综合保留调用空间，不静默提高限制。
- 单篇提取遇到格式类错误（`invalid_json`、`incomplete`、`refusal`、`no_text`）或证据校验失败时，只把该篇分析记为 `failed` 并继续下一篇；服务类错误（鉴权、配置、重试后仍失败的暂时性错误等）仍终止运行。
- 提取读取尚未提供过的3000字符窗口，单次最多18000字符，优先摘要和关注词/实验章节。保存精确全局字符区间与未读边界；缺失与字段冲突不以常识填平。新增片段的缺失不覆盖已经找到的事实，不同值保留并列。
- `analysis_revision` 随研究补充递增，旧范围和成果保留。来源/字段契约不变时引用旧事实；新增关注维度重新提取。有效结果与游标先在短事务中提交，再处理暂停，继续不重放已完成调用。
- 评估以当前筛选与有证据的字段为依据。同作版本按一组计算；组内字段完整率采用最低值，不挑最高版本抬高覆盖。默认关注六类基础字段，有显式关注维度时以其为分母；模型的“不适用”不能自行删掉分母。
- 有未提供的保存文本时优先补读，否则针对当前缺口生成不同查询。连续两轮没有新增有效资料或覆盖/字段改进、无新动作或达到硬限制时停止。重复引用 ID 不算进展。
- 综合输入保留有界证据/字段与比较条件，截断明确披露。每条综合主张只能引用实际提供的证据 ID。综合遇到格式类错误或校验失败时保留逐篇分析，生成未含综合章节的阶段性报告。报告保存后才发布终态：检索没有结果、达到执行限制、仅有资料或综合失败时生成阶段性报告并记为 `partial`；只有服务失败且没有任何可读资料时才记为 `failed`。`completed` 只表示达到操作性条件并生成报告，语义支持仍须人工复核。

## 无模型与模型变更

- 未配置模型时，研究按问题关键词检索 arXiv：去掉常见停用词后取最多8个词，以 `all:词1 AND all:词2 …` 组合，不再整句精确匹配；只保存检索结果和来源，不做结构化分析。提取不到关键词时运行失败并说明原因。
- 已经调用过模型的研究，在模型停用后继续执行时转为 `needs_input`，提示配置模型后继续，不改用无模型路径冒充原研究。

## 暂停、补充和继续

1. 执行中的用户请求暂停后标记 `pause_requested`；当前外部请求完成或超时后保存已完成结果和检查点，进入 `paused`，期间不发起下一次外部请求。界面显示“正在暂停”直至真正暂停。
2. 在 `paused` 或系统主动进入的 `needs_input` 状态，用户可追加文本；补充信息与原任务分别保存。继续前由用户显式触发，进入队列。
3. worker 先判断补充信息是否影响检索范围、子问题、筛选或报告要求；更新计划及相关性判断，保留历史论文、来源和证据，排除不再适用的结果。重新执行必要的后续阶段，记录调整原因。
4. 继续使用同一运行与累计调用数；暂停等待时间不计入运行时限，实际执行时间跨暂停累加。达到既有限制时按现有停止规则处理。
5. 对话为处理新消息而临时暂停的研究，在回答、澄清或对话失败后自动重新排队；补充研究方向时保存补充并按新范围重新规划后继续。用户自己暂停或系统进入 `needs_input` 的研究不自动继续。
6. 会话的停止按钮只停止正在进行的工作：待处理对话、排队或执行中的研究，以及被对话临时暂停的研究。用户自己暂停或等待补充的研究保留，可稍后继续。

前台是对话而不是阶段操作表单。首条消息可以触发澄清或研究；后续消息由对话层判断为资料追问、研究补充或执行控制。执行中的补充自动等待检查点，不要求用户先暂停。显式 `ask` 只使用已保存资料，不触发检索；终态后补充检索创建新 Run。原有暂停／补充／继续接口仍保留用于内部执行和兼容，详细规则见 [会话执行语义](<03-data-and-api.md#会话执行语义>)。

## 充分性：可检查的启发式

建议每个运行先得到用户关注的子问题；规划不得依赖“模型认为充分”作为唯一依据。默认候选阈值：至少 6 篇纳入论文；每个子问题至少 2 篇经筛选相关论文；各论文在用户关注字段中，有证据的非空字段比例平均至少 60%。分母只包含该任务适用的关注字段；没有适用字段时不计算该比例，并提示任务目标需调整。相关性可由模型或人工判断，其判断本身存在误差。

同时必须满足：每个关键论文事实有可定位证据，尚未解决的关键矛盾和缺口均被披露。这些规则仅决定是否达到系统的操作性停止条件，不能证明文献覆盖全面或结论正确。

示例：有 8 篇论文但“低资源场景”只有 1 篇相关文献时，数量满足、覆盖不满足；优先补充该子问题的查询。若只找到了摘要，方法字段可用摘要证据，但未提及的实验数据应标缺失；继续搜索不保证一定能获得全文。

若无新查询、两轮结果均无新增可用论文、来源不可用或达到执行限制，则停止继续检索，记录相应原因。未达到目标时生成阶段性报告并标记 `partial`（包括检索没有找到符合范围的论文，此时报告写明该缺口）；只有服务失败且没有可读资料时为 `failed`。若原定目标满足且报告已生成，标记 `completed`。

## 当前执行限制

| 限额 | 当前值 | 说明 |
| --- | --- | --- |
| 检索轮次 | 3 | 包含第一轮 |
| 候选论文 | 12 | 超出部分明确记为未审阅 |
| 全文 PDF | 3 篇 | 其余使用摘要 |
| 研究外部调用 | 20 次 | 模型、检索、PDF 下载及跳转、重试均计入 |
| 研究执行时间 | 900 秒 | 不含暂停等待；每次调用不超过剩余时间 |
| 对话 | 每轮 1 次模型调用、最长 60 秒 | 与研究额度独立，不能互借；会话没有累计上限 |

设置页显示的是上述实际生效值，只读。增加容量须按实际需求修改代码默认值，不能把建议偷偷变成更高预算。默认值不是质量保证。记录调用次数和运行时间；供应商提供 token 数据时记录和展示，未知时显示未知，不当作零。不统计费用，不提供金额预算、费用上限或超额拦截功能。

## 失败和证据

只针对可识别的暂时错误做有限重试，每次尝试都计入调用统计：模型的 `rate_limited`、`timeout`、`network_error`、`server_error` 最多重试2次，间隔2秒和5秒；arXiv 同类错误最多尝试3次，间隔5秒和10秒，并遵守请求间隔。无权限、错误配置或格式错误不重试，直接记录。结构化模型输出无法解析时记录失败，不能补造结果。报告中的引用 ID 和文本位置可由程序检查；语义是否支持结论需抽样人工核查。模型自评分不是正确率。

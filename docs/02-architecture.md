# 系统架构

状态：已有对话、资料收集、有界研究分析和三格式报告原型；真实服务兼容性与科研语义质量不由离线验证证明。

```mermaid
flowchart LR
    U[用户] --> V[Vue 3 + TypeScript]
    V -->|HTTP| A[FastAPI]
    A --> DB[(SQLite)]
    W[串行 worker / 状态机] --> DB
    W --> S[学术检索适配器]
    W --> M[模型适配器]
    W --> P[PDF 获取与解析]
    P --> F[(本地运行文件)]
    S --> X[arXiv]
    M --> Y[云端模型服务]
```

## 设计边界

- 界面偏好由前端管理：主题为亮色、暗色、跟随系统，默认跟随系统；首屏前应用主题并监听系统变化。配色通过语义变量覆盖主界面、资料区、菜单与弹窗，采用中性黑白灰。通用设置控制发送快捷键、默认消息模式和自动滚动；外观另控制对话字号与宽度。浏览器只持久保存这些非敏感偏好，不保存密钥或研究内容；存储不可用时仅当前页面生效。默认模式仅作用于未手动指定模式的对话。
- 对话导出直接使用前端已加载的会话快照：Markdown 包含消息和引用摘录，JSON 另含任务、运行和用量。不会读取其他会话、模型凭据或未发送草稿；论文全文与报告文件不打包，不能作为完整数据库备份。恢复默认偏好不调用模型／会话修改接口。
- 设置的研究与用量页分开展示当前会话／所选调研的实际消耗和服务端只读上限。直接使用已加载的 ConversationView 与 Run 保存值，随现有对话轮询更新；切换历史调研不被后续轮询重置。Token 缺失保持未知，已有记录上限不由默认上限覆盖，不新增全站统计或费用估算接口。
- 前端以对话为主：采用Codex桌面端式的窄侧栏、紧凑标题栏、连续助手正文、右对齐用户消息和稳定底部输入区。桌面侧栏可收起；论文、原文定位及报告作为按需资料区，执行过程可折叠。模型／消息模式与发送／停止在输入区操作，暂停／继续及用量保持可访问。非重叠轮询更新持久化结果，不伪装成模型 token 流或内部思维。
- 助手正文使用Markdown排版，禁用原始HTML和自动加载图片，危险链接协议由解析器入口过滤；引用仍通过结构化证据按钮打开已保存快照。后台刷新保留已有内容，不重新插入加载占位；仅在内容高度变化且用户允许跟随、仍接近底部时自动滚动。历史列表按实际更新时间排序，不因读取会话而置顶。
- 会话重命名独立于研究问题；删除在同一短事务内停止当前工作并软删除，回收站恢复不自动执行。独立回收站按服务端分页、搜索与排序；批量恢复和彻底删除在单一事务内完成，删除前检查目标会话的在途 worker，请求结束前拒绝清除；共用论文和来源由存储层按实际关联保留。
- 会话复用 Task 标识；独立保存用户／助手消息、消息处理状态和引用，每个会话可有多个 Run。HTTP 只追加并排队消息，不在请求中调用云模型。串行 worker 先处理对话，再推进研究；模型只能选择固定的回答、澄清、研究或执行控制动作。
- 执行中发送消息先请求检查点暂停；判断为补充时追加 RunMessage，重新规划后继续同一 Run。仅由该消息暂时停下的研究可以自动继续；用户主动暂停、无法解释、格式错误或服务失败不能被自动恢复。终态后补充检索创建新 Run，资料追问不创建研究运行。
- AI服务以供应商为配置单位：名称、协议、地址、一份凭据和多个已选模型ID。设置只负责配置、获取清单与删除；当前供应商和型号仅从对话菜单选择，保存不自动选择。正在使用的供应商只在空闲时修改／删除，不重置历史用量。
- 模型列表由服务端使用该供应商凭据请求 `/models`，不发送会话或调用生成，支持Anthropic分页；外部超时、鉴权、限流和格式错误明确反馈。浏览器只持有用户本次输入的密钥，不持久化或回显已保存凭据。更改地址不能直接复用旧密钥。
- 本机AI服务文件原子保存并优先于环境配置。已知旧单模型及profiles结构读取时迁移，协议／地址／凭据完全相同才合并为一家供应商，保留当前型号和不同凭据。旧文件直到下一次保存才改写。
- FastAPI 负责输入、查询、消息排队、启动、暂停、补充、继续和取消请求，返回持久化状态。一次运行保留最初输入和按时间追加的补充信息；暂停后继续同一运行，终态后的重新执行创建新运行。
- worker 与 FastAPI 共用应用 lifespan，在同一进程串行处理对话和研究。异步外部调用不会以同步等待阻塞 HTTP；首期仅一个后端进程／worker，不使用每请求 BackgroundTasks 或分布式队列。
- SQLite 保存任务、运行、查询、论文、证据和报告元数据；数据库与本机 AI 服务设置保存在 `DATA_DIR`（默认 `data/`）；报告导出由浏览器直接下载，服务端不另存导出文件。SQLite 适用本地单机和低写入并发；事务不跨网络请求。
- 检索、模型和 PDF 各自提供窄接口；检索源负责转换外部格式，业务规则不放入适配器。首期接入 arXiv；目标网络的可达性仍需实际验证。
- 云端模型协议分别实现 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 适配器，用户选择协议、服务地址、模型与凭据；不同服务对可选能力的支持需要单独核验，不假定完全兼容。
- 研究分析由 `analysis.py` 处理结构化输出、输入范围与引用验证、论文分组、实验可比性和覆盖口径；`engine.py` 控制筛选、读取、提取、评估、综合与检查点。适配器仍只负责协议请求，不承载研究规则。
- `analysis_revision` 区分同一 Run 的范围修订，提取记录及输入区间不可变；来源与关注字段契约相同时显式复用事实，相关性和覆盖按新范围重算。纯资料问答不创建分析修订。
- 当前报告同时保存结构化快照和 Markdown。`reports.py` 从同一快照生成 Markdown、Word/PDF，报告与终态在同一事务中发布；前端下载绑定报告 ID，不因最新报告变化而换版、不新增模型调用。历史 Markdown 不倒推结构化结论。
- 启动 worker 时将上次遗留的执行中或等待暂停的任务标为中断，保留记录；已暂停或等待补充的任务保持原状态。中断后用户可发起新运行。该规则依赖单 worker，不能直接用于多 worker 部署。

## 模块职责

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| 任务服务 | 用户问题与范围 | 任务与不可变运行快照 |
| 规划 | 研究目标、已有缺口 | 子问题、关键词和检索条件 |
| 检索与整理 | 查询与来源 | 原始记录、规范化论文、去重关系 |
| 内容处理 | 论文记录与允许访问的 URL | 摘要或按页提取的文本、读取状态 |
| 提取与比较 | 已读取文本和关注维度 | 字段、来源定位、缺项及比较 |
| 评估 | 目标、论文、证据和执行限制 | 覆盖结果、缺口、继续或终止原因 |
| 报告 | 经检查的分析与来源 | 可读报告与参考文献 |

## 目录结构

```text
backend/app/
  api/              # 路由和请求响应
  domain/           # 类型与状态
  workflow/         # 状态机与串行 worker
  adapters/         # arXiv、模型、PDF 获取与解析
  storage/          # SQLite 与会话持久化
  analysis.py       # 筛选、提取、比较与评估规则
  dialogue.py       # 对话动作与追问来源
  reports.py        # 报告快照与三格式渲染

  components/       # 对话之外的资料区、设置、回收站等组件
  composables/      # 主题、偏好与菜单关闭
  api/              # 后端 HTTP 客户端
tests/              # 关键行为测试、浏览器回归脚本
```

## 内容及安全边界

服务端只接受配置允许的学术源提供的公网 PDF 地址；对每次重定向重新检查目标，拒绝回环、内网和本机服务，限制下载体积与解析时间。这些措施针对自动获取外部 URL 的直接风险，按最小实现。PDF 文本解析失败、扫描件、表格丢失须标明缺项，不做 OCR。下载或读取某页不证明表格数值解析正确。

模型部署方式已确定为云端；用户问题、摘要和用于分析的全文片段可能发送给供应商。具体供应商、发送范围及其数据处理政策仍需在接入时确认。日志记录操作、错误类别和计数，不记录密钥或整篇原文。

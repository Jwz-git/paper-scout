# 需求与验收

状态：首期范围已确认，验收参数为建议值；2026-10-29。

## 目标与范围

为计算机领域提供本地单用户文献调研原型：输入研究问题，检索论文，读取摘要和可访问的文本型 PDF，提取可追溯信息，按缺口迭代，生成比较与报告。输出辅助科研人员核查，不代替阅读原文。首期无用户上传、OCR、多用户权限、自动实验和投稿。首期使用用户自定义云端模型与 arXiv 检索；实际模型服务能力及 arXiv 在目标网络的可达性尚待验证。

## 功能需求

| 编号 | 功能 | 验收条件 |
| --- | --- | --- |
| FR-01 | 任务输入 | 填写问题，支持年份范围、关注维度和输出要求；无效范围在提交时说明原因。 |
| FR-02 | 理解与计划 | 展示结构化主题、子问题、关键词、检索源和时间范围；歧义影响检索时说明需补充的信息。 |
| FR-03 | 检索与去重 | 保存每轮关键词、来源、时间、结果数和失败原因；按 DOI、来源 ID 及审慎的标题作者规则合并，疑似重复保留供核查。 |
| FR-04 | 内容读取 | 区分元数据、摘要、已读取的全文页；记录全文获取、解析失败或不可读原因。 |
| FR-05 | 信息提取 | 对研究问题、方法、数据集、指标、结果和局限记录值、证据与缺失原因；未读取的信息不得编造。 |
| FR-06 | 跨文献比较 | 按统一维度展示论文信息、原文来源和缺项；实验条件不一致时标注不可直接比较。 |
| FR-07 | 充分性与迭代 | 展示各子问题覆盖和关键字段缺口；有明确缺口且执行限制允许时生成不同查询，达到终止条件时记录原因。 |
| FR-08 | 报告 | 展示背景、检索范围、研究分类、方法比较、证据、局限和参考文献；默认导出 Markdown，也可导出 Word（.docx）和 PDF，各格式保留引用与缺口。 |
| FR-09 | 任务记录 | 查看任务历史、进度、每轮记录、论文和报告；失败或中断后可由用户重新运行。 |
| FR-10 | 资源管理 | 限制轮数、调用次数和时间；达到限制后停止新增调用并保留已完成结果。 |
| FR-11 | 模型配置 | 用户可配置协议、服务地址、模型和凭据；分别支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages，错误明确展示，凭据不显示在日志或结果中。 |
| FR-12 | 暂停与补充 | 用户请求暂停后，在当前外部请求完成或超时后的检查点停止；补充信息并继续同一运行，保留历史、证据及累计用量，检查补充信息对计划和已有结果的影响。 |

## 非功能要求

- 可追溯：关键论文事实可定位到实际读取的摘要或全文文本；系统推断与论文作者主张分别标记。定位存在不代表语义一定正确，人工复核仍必要。
- 可靠：服务无结果、限流、失败、信息缺失和任务中断分别呈现；不通过虚构内容完成报告。
- 可扩展：检索、模型和 PDF 处理通过明确接口接入；不预建未使用的插件体系。
- 资源可控：记录实际调用次数和执行时间；可获得时统计 token 与费用。首期不设置金额预算；模型价格和用量口径随具体供应商核验，未知值不记为零。
- 安全：密钥只存服务端；限制不可信论文 URL 的访问目标、下载体积和解析时间；远程论文内容不能指挥工具执行。
- 易用：界面展示当前阶段、已收集论文、缺口和终止原因，用户可查看来源并导出；当前建议采用类似 Codex 的对话加过程展示，具体布局后续可调整。

## 最小演示验收

使用一个有明确子问题的计算机领域主题，运行真实检索并保留查询过程；展示至少一篇摘要和可访问文本型全文的提取与定位，至少一次缺口驱动的补充查询，比较表和带来源报告。若实际资料足够，使用预先设计的缺口案例验证迭代；若网络、模型或全文不可用，明确记录阻塞，不能把离线样本冒充真实演示。

研究质量的量化目标和评估样本尚未约定，建议方法见 [开发与评估](05-development-and-evaluation.md)。

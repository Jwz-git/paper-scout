记录日期：2026-10-29。已确认事项来自本次用户答复；建议和待定不是既成事实。

## 已确认

| 决策 | 内容 | 影响 |
| --- | --- | --- |
| 交付 | 本地单用户课程／毕设原型 | 首期不做账号、多人权限和线上部署 |
| 前后端 | Python＋FastAPI；Vue 3＋TypeScript 独立前端 | 需要定义 HTTP 接口并分别管理依赖 |
| 编排 | Python 显式状态机＋模型工具适配器 | 阶段、缺口与停止原因可观察，不依赖特定智能体框架 |
| 模型与检索 | 用户自定义云端模型；支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；首期检索 arXiv | 用户配置协议、服务地址、模型与凭据；需验证实际服务能力、网络可达性和 arXiv 使用条件 |
| 报告 | 默认 Markdown；支持 Word（.docx）和 PDF | 首期各格式应保留相同报告信息及引用 |
| 交互与暂停 | 可暂停、补充信息并继续当前运行；当前方向参考 Codex 对话形式，界面可调整 | 暂停在当前外部请求结束后的检查点生效，保留结果与累计用量，继续前重新检查计划 |
| 学校约束 | 用户表示没有额外硬性要求 | 按已约定范围和验收方案推进 |
| 全文 | 自动获取允许访问的文本型 PDF；上传后续 | 需处理无全文、扫描件及解析失败；不做 OCR |
| 开发约束 | 禁止不必要防御性编程、哈希验证和例行冒烟测试 | 必要边界检查和核心行为测试应说明实际必要性，见 AGENTS.md |
| 费用与用量 | 不做金额预算功能；用量统计保留 | 保留轮次、调用次数和时间限制；可获得时统计 token 和费用 |

## 建议方案

| 议题 | 建议及理由 | 何时调整 |
| --- | --- | --- |
| 数据存储 | SQLite＋本地文件：单用户部署简单、可保留任务历史 | 需要多用户并发写入或远程服务时重新设计 |
| 执行方式 | 单串行 worker：状态可持久化，避免长任务阻塞 API | 有明确并发吞吐需求时再评估队列 |
| 全文提取 | 先评估 pypdf 按页提取文本，保留页码和缺失 | 表格、版面等质量不够时按样本更换或补充解析器 |
| 执行限制 | 见流程文档中的建议值 | 模型、时限和质量基线确定后调整 |

## 仍需讨论或实测

1. **云端模型服务**：协议范围已确定，用户自行选择服务地址与型号。实际供应商对结构化输出等能力的支持及可达性仍需验证；不要在聊天或仓库提供密钥。
2. **隐私及文本发送**：已选择云端模型；实际发送哪些研究问题、摘要和全文片段，以及供应商的数据处理政策，仍需随具体服务确认。
3. **arXiv 接入**：首期已选 arXiv，但目标网络可达性尚未实测。需验证查询、限流和全文样本；预印本不能等同于同行评审成果，单一来源也不能代表领域全部文献。
4. **评价样本和最低质量阈值**：尚未约定；建立基线并人工核查后制定，不影响先行开发。
5. **执行限制和效果阈值**：文档的轮次、论文数和覆盖率仅为初始建议，须对实际课题运行、人工核查后调整。

这些事项不阻止完成设计文档，但会影响真实接入和最终验收。确定后更新对应文档和本记录。

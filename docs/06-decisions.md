## 仍需讨论或实测

1. **云端模型服务**：协议范围已确定，用户自行选择服务地址与型号。实际供应商对结构化输出等能力的支持及可达性仍需验证；不要在聊天或仓库提供密钥。
2. **隐私及文本发送**：已选择云端模型；实际发送哪些研究问题、摘要和全文片段，以及供应商的数据处理政策，仍需随具体服务确认。
3. **arXiv 接入**：首期已选 arXiv。初始化阶段曾记录2026-11-02单次 API 可达；该观察不代表持续可达、PDF 下载成功或真实服务验收。本轮仅使用离线样例和HTTP替身回归，未重新验证当前网络。生产调用配置要求请求间隔至少3秒；缺失PDF链接不拼接，预印本不等同于同行评审成果，单一来源不代表全部领域。
4. **评价样本和最低质量阈值**：尚未约定；建立基线并人工核查后制定，不影响先行开发。
5. **执行限制和效果阈值**：文档的轮次、论文数和覆盖率仅为初始建议，须对实际课题运行、人工核查后调整。

这些事项不阻止完成设计文档，但会影响真实接入和最终验收。确定后更新对应文档和本记录。

## 2026-11-02 代码审查实施决定

用户授权检查并修改代码（允许重构）。对应依据与回归记录见 [代码审查记录](<08-code-review.md>)。

- 落实 SQLite 和单进程串行 worker；不使用每请求 BackgroundTasks 并发执行长任务，不增加分布式队列。应用寿命管理数据库与 worker，测试可注入隔离实例。
- 原始输入、当前范围、查询／读取游标、累计用量持久化；API 控制状态是事实来源，旧 worker 快照不能抹掉暂停或取消。
- 增量迁移已知旧 schema，不重建用户数据库；每运行论文快照与文本只追加，字符定位在证据保存边界核对。旧运行缺失完整初始范围时标记未知。
- 语义字段、引用支持核验与充分性评估尚未实现，因此撤销“论文数达到2即 completed”的逻辑。有可核查文本只交付 `partial` 阶段性资料报告，无可核查文本为 `failed`。这是纠正能力描述，不是取消科研分析目标。
- 模型未配置时只进行披露的简单检索；有补充而无法解释时进入 `needs_input`。配置模型后重新规划必须明确历史论文选择，补充、范围与检查点原子保存。
- 外部调用计数发生在真实请求边界，含失败与PDF跳转；arXiv等待限流期间可以暂停且不提前计数。执行时间不包括暂停等待，时限取消的已发起检索保留失败记录。
- PDF逐跳验证公网目标并固定连接IP，保留TLS证书校验；解析子进程能在超时／取消时被回收，不伪造页码或OCR。
- 原首期需求仍包含Word／PDF报告导出；当前只实现Markdown，后续实现需保留同样的来源和局限。

运行默认值与实际验证见 [README](<../README.md>)；外部服务可达性、供应商可选参数兼容性、依赖安全审计和浏览器联调仍未验收。

## 2026-11-03 对话交互修复决定

用户指出实现成工作流控制台而不是类似 Codex 的对话界面，并要求彻底修复。原“参考对话形式、布局可调整”不能作为继续保留强制表单流程的理由。

- 对话成为主入口：真实消息时间线、统一输入、会话历史；执行阶段、论文与报告作为辅助信息。
- 后台保留显式状态机，不将“对话 UI”与“可靠工作流执行”视为互斥。追加会话消息、固定动作路由和有来源的资料追问；不新增通用工具执行或智能体框架。
- Task 复用为会话，新增消息和轮次记录，不删除已有数据库、报告或来源。旧任务输入不冒充助手回复。
- HTTP 排队消息，单 worker 串行处理消息和研究；请求标识防止网络不确定时重发导致重复调用。已发起但中断的对话不自动重放。
- 研究中补充自动走安全检查点，保留同次运行和累计用量；人工暂停不会因追问被自动解除。终态后的新检索创建新运行，资料追问不暗中检索。
- 对话引用核对本会话来源和精确原文，语义支持仍需复核；无模型模式明确披露能力缺口，不用固定模板伪装智能回答。
- 不新增运行依赖，不改三种云协议或假定新供应商能力。未提交或推送本轮改动。

实际行为、必要验证及未验收项见 [对话交互修复](<09-conversation-interface.md>)。

## 对话交互验收方案

M1/M3 的交互验收包括：统一对话输入、可恢复的真实消息历史、执行中补充、澄清与资料追问、可核查引用和按需资料区；执行上限按轮计算，会话与工作区分别累计用量。交互验收不等于完整 M3/M4 科研能力已完成。

| 场景 | 验收要求 | 必要性 |
| --- | --- | --- |
| 网络不确定后重发 POST | 同标识同请求读取原记录，冲突复用报错 | 防止重复模型调用和费用 |
| 执行中补充 | 补充在下一次模型调用前并入当前轮，已开始的工作留在原消息下，后续工作和回复出现在最新消息下；模式以最新消息为准 | 防止补充丢失，或切换到“只用已有资料”后仍继续检索 |
| 已有资料追问 | `ask` 模式下拒绝检索和新的全文下载；回复只能引用本会话工作区已保存的证据 | 防止隐式检索、跨会话引用和虚构原文 |
| 处理中的对话停止 | 无工作区也可停止；在途请求被取消，迟到结果不覆盖停止状态 | 保证用户能阻止待处理工作 |
| 进程重启 | `processing` 标为 `interrupted`，尚未发起的 `queued` 保留 | 防止重放可能已经收费的请求 |
| 用量视图与运行切换 | 会话与工作区／旧运行分别计量，显示实际生效的每轮上限；轮询保留用户选择的历史运行，缺失Token保持未知；查看用量不发起模型或修改请求 | 防止范围混淆、错误预算展示与未知值被当作0 |
| 回收站批量管理与彻底删除 | 搜索／分页不漏记录，全量操作不截在100条；取消不执行；失败保留记录；只删除回收站对象，原子处理，保留共用来源，在途请求结束前拒绝彻底删除 | 防止不可逆误删、残留关联与在途结果回写 |
| 切换会话、运行及来源 | 草稿相互独立，旧请求不回写新视图，引用打开正确快照 | 防止串会话、串运行和错误来源展示 |
| 对话正文与后台刷新 | Markdown不执行HTML或自动加载远端图片；已加载过程／资料刷新不插入加载段落，无变化轮询不重置文本选择和阅读位置；新内容按滚动偏好跟随 | 防止不可信回复触发外部行为，以及轮询导致界面抖动／打断阅读 |

前端类型检查、构建和离线浏览器交互验证不代替真实供应商与科研语义验收。浏览器脚本依赖不随仓库安装的 playwright-core：先在仓库根目录执行 `npm install --prefix temp/ui-verification --no-save --package-lock=false playwright-core@1.64.1`（`temp/` 已被 Git 忽略），再在 `frontend/` 执行 `npm run build`，之后在仓库根目录运行脚本；可选场景为 `chat/controls/settings/basics/theme/preferences/trash/usage/analysis/catalog`。`BROWSER_SCENARIO=chat node tests/browser_conversation.mjs` 使用人工Markdown及受控延迟响应，验证刷新稳定性、滚动跟随、文本选择、侧栏焦点和窄屏菜单。各次执行结果与故障经过单独存放于 `changelog/`，本文件只规定验证方法和通过条件。

## 必要测试

针对核心规则设计少量行为测试，固定样本和模型／检索替身用于可复现执行，不连接付费服务：

1. 相同 DOI 的跨源记录合并；仅标题近似时保留疑似项，论文版本差异不被抹掉。
2. 摘要未提及的数据集或数值保持缺失，证据只定位到实际读取文本；无效引用不得成为报告事实。
3. 步数、调用、时间上限分别触发收尾，收尾只允许回复，收尾也失败时由代码生成概况；无效输出交回模型改正，连续 3 次无效时进入收尾；暂时性错误有限重试并计入调用。
4. 执行中补充在下一步并入且沿用同一工作区和额度；停止取消在途模型请求，重启将处理中的消息标为中断；阅读子 agent 并发受限并共用本轮预算。
5. 可比较与不可比较的实验设置得到不同标记；PDF 读取失败不会被当作全文已读；三种导出格式包含同一组来源和缺口。
6. 三种模型协议分别使用可控的接口样例验证请求、响应和错误转换，不假定第三方兼容服务支持全部可选能力。

定向测试使用 pytest，协议和外部来源使用明确离线替身；agent 循环、上限、插话、停止与子 agent 在 `tests/test_agent.py`；引文定位与比较在 `tests/test_analysis.py`；报告版本与三格式在 `tests/test_reports.py`；HTTP 与 worker 链路在 `tests/test_conversation_integration.py`、`tests/test_conversations.py`。命令按实际变更范围选择，无需为了每次修改增加冒烟测试；文档变更核查链接和内容即可。

## 标注文件与本地评价

`tests/fixtures/evaluation_template.json` 是全未知标签的人工模板，不包含真实论文。每个案例保存主题、`sample_kind`（`real_public/artificial`）、报告 ID、可选人工参考论文集、检索相关性、字段正确性、引用语义支持、子问题覆盖及复核备注。标签为true/false/null；null代表未复核，不计为正确、错误或零。

```bash
.venv/bin/python -I scripts/evaluate_research.py <人工标注JSON文件>
```

脚本只读取明确指定文件，在本地输出逐案例的分子、分母、未知数和比例，不访问模型或网络；未建立参考集时样本召回为未知。人工样例与真实样本不混合汇总，脚本不设置质量达标线。标注须由原文复核产生，不能直接抄用模型自评或定位校验结果。

新增核心反例包括：原文存在但不在本次输入范围、非BMP字符定位、字段缺失、未读范围的摘录被拒绝、同作版本不重复计数、不同划分/协议不直接比较、停止后不再发起调用、报告引用已排除论文被拒绝，以及三格式绑定相同报告ID。浏览器使用既有 `BROWSER_SCENARIO=analysis node tests/browser_conversation.mjs` 定向场景；其导出响应为人工样例，实际DOCX/PDF内容由后端测试另行验证。

真实验收须使用另获授权的公开主题、指定服务和隔离验收数据。记录供应商能力/日期、发送范围、实际调用与失败；人工检查至少摘要、文本型全文、一次缺口补检、阅读子 agent、执行中补充、比较表与报告。模型不可用、网络不可达或未经许可发送时，明确保留待验收，不能把离线HTTP/worker链路冒充真实验收。

## 质量评估设计

先选多个不同子领域、明确时间范围及子问题的公开课题，建立人工标注的候选论文集与证据样本。明确标注者、检索范围和纳入标准；样本不等于领域全部论文。建议至少两名评审独立核查分歧，人员不足时如实说明单人评估限制。

| 指标 | 计算方法 | 边界 |
| --- | --- | --- |
| 检索精确率 | 人工判定相关的系统返回论文数 / 人工检查的返回论文数 | 对应具体主题和结果截断数 |
| 样本召回率 | 系统找到的标注相关论文数 / 标注相关论文总数 | 只能代表标注样本，不代表全库召回 |
| 子问题覆盖率 | 至少有一篇人工确认相关论文的子问题数 / 子问题总数 | 不证明研究方向已全面覆盖 |
| 字段准确率 | 与原文一致的已抽查字段数 / 已抽查字段数 | 分别统计摘要和全文；缺失单独统计 |
| 引用支持率 | 原文确实支持主张的抽查引用数 / 抽查引用数 | 有效链接和文本位置不等于语义支持 |
| 运行消耗 | 每任务墙钟时间、外部请求数、模型调用数、可得 token | 缺乏计量的字段标未知，记录环境和服务 |

记录抽样方式、分母、原始判断和冲突案例；不把模型自评分当作准确率。分别统计充分终止、执行限制终止、来源失败和解析失败比例。阈值及通过标准在确定验收要求和建立基线后制定，不先虚构达标线。

示例报告需注明研究问题、检索日期、数据源、时间范围、纳入与排除原因、来源快照／链接、证据缺口和人工复核情况。只提交允许公开的样本与报告。

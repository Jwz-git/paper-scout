# 对话交互修复

日期：2026-11-03。依据：用户指出现有工作流界面与 Codex 式对话方向不符，并要求“彻底修复”。本轮修复交互和消息执行链路，不把资料收集原型升级描述为完整科研分析系统。

## 问题与交付边界

原主界面是任务表单、阶段步骤、运行选择器和暂停后的补充表单。用户只能沿着“创建—执行—暂停—保存补充—继续”操作，任务补充不是完整对话。将表单换成聊天气泡不能解决消息持久化、澄清、执行中调整和资料追问。

修复方向：

- 左侧历史会话，中间真实对话时间线和统一输入框；不预填假任务，不伪造模型思维或流式 token。
- 执行状态与暂停／继续／取消是辅助控制，过程记录折叠；论文、来源和 Markdown 报告按需打开。
- Task 作为会话，多个 Run 作为该会话的研究执行历史。消息独立保存，不删除或改写既有来源和研究快照。
- `auto` 由模型判断回答、澄清、研究或控制；`research/ask/pause/resume/cancel` 是用户显式覆盖。`ask` 不触发新检索。
- HTTP 只排队。对话和研究由同一单进程串行 worker 执行，不新增分布式队列或每请求后台调用。

## 执行与消息语义

1. 创建会话及追加消息返回 `202` 和当前会话视图；用户消息与待处理助手消息成对持久化。
2. `request_id` 标识一次发送。相同内容重发读取原记录，冲突内容返回 `409`，不自动重试模型请求。同会话只允许一个待处理对话轮次。
3. 执行中收到消息，先在外部请求结束或超时后的检查点暂停；新方向进入原 Run 的补充机制，重新规划并核对历史论文后继续。暂停等待不计研究执行时间。
4. 仅为这条消息临时停下的研究可以自动继续；人工暂停、需要补充、无法解释或消息失败不会被隐式恢复。消息处理与实际动作关联保存。
5. 终态后的新研究创建新 Run，旧报告和来源保留。资料追问使用已保存快照，回答本身不新建研究或查询；仅为问答临时暂停的原有研究可以恢复，并在回复中说明。
6. “停止当前工作”直接中断排队／处理中的对话并取消活动研究；尚无 Run 的首轮对话或资料回答也可停止。迟到模型结果／错误不会覆盖停止状态或启动研究；已发起请求仍可能完成，调用及可得用量继续计入。
7. 没有模型时明确说明简单关键词检索及显式控制的范围；不假装能理解任意中文补充或作语义回答。无法处理时保留用户文本并显示原因。
8. 进程重启将已开始处理的对话标记为 interrupted，不重放可能已经收费的请求；尚未发起的 queued 消息可以执行。

已发送消息与处理状态保存在服务端。未发送草稿及待确认的请求标识只在当前组件会话中保留，切换对话不丢失，但尚不承诺刷新／关闭浏览器后恢复；界面不会将草稿或密钥写入浏览器持久存储。

## 引用、上下文与用量

对话只给模型有界的会话历史与已保存的来源片段，披露截断和缺失；论文内容是数据，不是指令。模型不能选择任意 URL、命令或工具。引用必须匹配本会话所提供的运行、论文、快照和实际原文字符区间；无效引用使该回答失败，不能降级成无来源的“成功”。界面允许打开对应来源、页码与原文片段。

**字符定位一致仅证明引用原文存在，不证明原文语义支持回答。** 模型生成的归纳仍需人工复核；无资料、只有摘要、部分全文、复杂表格和扫描件均不应被宣称已完成可靠科研比较。

对话与研究分别显示实际模型调用、执行时间和可得 token。失败的已发起请求计入用量；未知 token 保持 null，不记为零。对话默认累计上限为40次模型调用、900秒执行时间，每次调用不超过60秒或剩余时间；研究沿用既有20次外部调用、900秒和轮次限制，不因继续对话重置同一 Run 的预算。

## 必要验证与结果

本轮仅为具体失败方式增加检查：重复发送导致重复付费、补充与控制竞态导致消息丢失或误恢复、外来或虚构引用污染答案、进程重启重放调用，以及会话切换导致过期响应写入。没有新增例行冒烟套件、哈希验证或运行依赖。

已分批实际执行：

| 范围 | 命令与结果 |
| --- | --- |
| 新对话持久化、消息幂等、控制竞态、来源与预算 | `PYTHONPATH=. .venv/bin/python -m pytest tests/test_conversations.py -q` → `45 passed in 0.23s` |
| 受影响的原存储、工作流、任务／运行及健康接口 | `PYTHONPATH=. .venv/bin/python -m pytest tests/test_storage.py tests/test_workflow_engine.py tests/test_api_tasks_and_runs.py tests/test_api_health.py -q` → `41 passed in 0.22s` |
| 真实应用 lifespan、HTTP、串行对话／研究、报告与资料追问 | `PYTHONPATH=. .venv/bin/python -m pytest tests/test_conversation_integration.py -q` → `1 passed in 0.05s` |

这些是分别执行的定向回归，不是最新一次整仓全量测试。最后发现旧骨架允许保存无运行的空主题／无效年份任务：读取历史时不应重新套用新入口校验并报错。因此仅修改旧记录展示，原值明确标为未经新输入校验；随后执行 `PYTHONPATH=. .venv/bin/python -m pytest tests/test_conversations.py -k 'legacy or worker_rechecks' -q` → `3 passed, 43 deselected in 0.08s`，当时46个对话用例分批验证。

随后修复了“尚无 Run 时无法停止模型对话”的实际交互缺口，只执行新增停止相关用例：`PYTHONPATH=. .venv/bin/python -m pytest tests/test_conversations.py -k stop -q` → `7 passed, 46 deselected in 0.11s`。当前53个对话用例已分别验证，未重复运行未受影响用例。停止后迟到的成功、错误、关闭取消和旧队列快照均不能复活研究。

集成案例使用真实应用与持久化/worker，但模型、检索和论文内容均为明确的离线人工替身。未据此验证真实网络、供应商或科研答案准确率。

### 前端与浏览器

- 最终 `frontend/` 中 `npm run build` 成功（`vue-tsc -b`＋Vite，18个模块，退出码0）。在停止控制、引用切换下载和来源／滚动版本修复后重新构建，而非无变更重复运行。
- `node tests/browser_conversation.mjs`：真实本机 Chrome，6类定向场景通过：空白对话入口、独立草稿、执行中补充与同请求重发、正确运行来源与 Unicode 原文高亮、延迟旧会话响应隔离、移动端布局／无未捕获 JS 错误。
- `BROWSER_SCENARIO=controls node tests/browser_conversation.mjs`：最终构建上验证初次创建失败后切换与原请求重试、无 Run 的处理中对话直接停止、停止后的过期轮询与草稿保护；更新最终移动端截图并确认无未捕获 JS 错误。未重跑未改变的其他场景。

浏览器测试把构建资源和全部 API 请求在本地拦截，使用明确的人工会话／论文样例；**没有启动替代服务器、访问真实供应商、读取用户资料，或把虚构论文当真实研究结果。** 这是实际浏览器里的离线交互验证，不是 Paper Scout 当前运行服务与真实云模型的联调验收。

复现浏览器验证使用现有 Chrome 和独立临时工具，不修改项目依赖及锁文件：

```bash
# 仓库根目录，临时浏览器驱动由 Git 忽略
npm install --prefix temp/ui-verification --no-save --package-lock=false playwright-core@1.64.1
# 先在 frontend/ 执行 npm run build
node tests/browser_conversation.mjs
BROWSER_SCENARIO=controls node tests/browser_conversation.mjs
```

其他系统通过 `CHROME_EXECUTABLE` 指定 Chrome 可执行路径。截图保存在忽略的临时验证目录，没有加入真实研究数据。脚本见 [浏览器定向回归](<../tests/browser_conversation.mjs>)。

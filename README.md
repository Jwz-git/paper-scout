# Paper Scout

Paper Scout 是一个本地单用户的 AI 科研文献调研原型工具。它将**对话式交互**与**后台显式状态机**解耦，支持通过自然语言对话发起调研、动态补充条件与追问资料，自动化执行 arXiv 检索、PDF 文本提取，并生成附带精确原文证据的阶段性 Markdown 调研报告。

> **当前阶段声明**：已实现有界的论文筛选、结构化提取、实验条件比较、缺口驱动迭代及 Markdown/Word/PDF 报告原型，并有离线定向验证。真实供应商兼容性、目标网络与科研语义质量仍需独立验收；引用原文可定位不等于主张已被证明，`completed` 只表示达到本次操作性条件并保存报告。

---

## 核心特性

- **对话式调研协作**：采用Codex式窄侧栏、连续Markdown回复与底部输入区；通过自然语言描述目标（如“检索多智能体通信近三年工作”）。模型与消息模式在输入框内切换，支持执行中补充指令、暂停／继续及停止；资料与报告按需打开。后台刷新保留阅读位置，不以加载占位反复挤动正文。
- **可追溯的事实证据链**：区分元数据、摘要与实际解析的 PDF 页面；关键报告结论关联精确的原文摘录、字符区间与来源快照，拒绝凭空臆造。
- **结构化分析与比较**：提取研究问题、方法、数据集、指标、结果、局限及关注维度；字段关联精确证据或缺失原因。保存筛选理由、同作/版本分组和疑似重复；实验条件相同、不同、缺失分别表示，不自动生成总体优劣排名。
- **缺口与有限迭代**：查询关联子问题，按覆盖和字段缺口补检或补读；同次运行补充范围后保存新的分析修订，不覆盖历史来源或重置用量。
- **三格式报告**：同一报告快照生成 Markdown、Word、PDF；报告主张可跳转原文，下载不再调用模型。历史无结构化快照的报告仍只提供原有 Markdown。
- **多模型供应商与协议**：支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 协议；支持本地管理多家供应商凭据、拉取或手动输入模型清单，并在对话中按需切换。
- **严格的资源与执行预算**：显式状态机限制单次运行的轮次、检索量、PDF 下载/解析时限（单篇最大 25 MiB / 50 页 / 10 秒超时）与外部调用次数，杜绝无限死循环与意外消耗。
- **本地优先与隐私安全**：单用户架构，运行数据与凭据均保存在本地（SQLite 与本地 JSON 配置），支持会话重命名、软删除回收站与导出。

## 技术架构

- **后端**：Python 3.9+ / FastAPI / SQLite / 显式状态机执行引擎
- **前端**：Vue 3 / TypeScript / Vite
- **适配层**：arXiv API 客户端、PDF 文本解析器、标准化 LLM 协议适配器

## 快速上手

### 1. 环境准备

确保本机已安装：
- Python 3.9+
- Node.js 18+ 与 npm

### 2. 一键启动（已安装依赖）

在项目根目录执行：

```bash
sh scripts/start.sh
```

前端地址为 `http://127.0.0.1:5173`，后端地址为 `http://127.0.0.1:8000`。终端会显示两个服务的日志，按 `Ctrl+C` 一起停止；任一服务退出时，脚本也会停止另一个服务。端口不可用时直接退出，不会结束已有服务或自动换端口。

脚本复用 `.venv`、前端依赖和现有应用配置，不自动安装依赖、不修改配置，也不主动创建研究任务；应用启动后仍按原有规则处理已排队任务。首次使用请先按下方步骤安装后端依赖，并执行 `npm --prefix frontend ci`。也可以从其他目录通过脚本的完整路径启动。

### 3. 手动启动后端

```bash
# 克隆仓库并进入根目录
git clone <repo-url>
cd paper-scout

# 创建并激活虚拟环境
python3 -m venv .venv
source .venv/bin/activate  # Windows 用户: .venv\Scripts\activate

# 安装固定依赖
pip install -r backend/requirements-lock.txt

# 运行定向回归测试（离线运行，无需外网）
PYTHONPATH=. pytest -q

# 启动本地后端服务（默认监听 127.0.0.1:8000）
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

### 4. 手动启动前端

在另一个终端窗口中进入 `frontend/` 目录：

```bash
cd frontend

# 安装依赖
npm ci

# 启动前端开发服务器（开发端口 5173，API 自动代理至后端 8000）
npm run dev
```

启动完成后，在浏览器中访问：`http://127.0.0.1:5173`。

## 配置说明

### AI 服务配置（推荐在 Web 界面完成）

1. 启动并打开前端页面后，点击左下角 **设置 → AI服务**。
2. 添加供应商：选择协议（`openai_chat`、`openai_responses` 或 `anthropic_messages`），填写 Base URL 及 API Key。
3. 点击“获取可用模型”或手动录入模型 ID。
4. 在对话输入框下方的模型选择菜单中，选中目标供应商与型号即可开始使用。

> 凭据保存在本地数据目录下的 `model-settings.json`（权限 600），前端不会回显或持久化明文 API Key。

### 环境变量配置（可选）

如需无前端或初始化时通过环境变量指定模型，可复制模板：

```bash
cp .env.example .env
```

核心配置项说明：
- `LLM_PROTOCOL`: 接口协议类型（`openai_chat` | `openai_responses` | `anthropic_messages`）
- `LLM_BASE_URL`: API 基础地址（如 `https://api.openai.com/v1`）
- `LLM_MODEL`: 使用的模型 ID
- `LLM_API_KEY`: 供应商 API Key
- `DATA_DIR`: 可选，本地运行数据存放目录（默认为仓库根目录下的 `data/`）
- `ARXIV_RATE_LIMIT_SECONDS`: arXiv 请求间隔（默认 3.0 秒）

> 若所有 LLM 配置均为空，系统将以**无模型资料检索模式**启动，仅支持基于关键词的简单检索与资料展示，无法自动理解复杂语义补充。

## 分析与报告

在对话右侧打开 **资料与报告**：

- **文献**：查看字段、缺失原因、作者自述/系统推断，以及实际提供给模型的片段；点击“查看依据”定位原文。
- **分析与比较**：查看筛选记录、子问题覆盖、字段分母、实验可比性和缺口。模型判断仍可能错误，比例不是准确率。
- **研究报告**：查看有引用的综合内容与完整 Markdown，并下载绑定当前报告 ID 的 `.md`、`.docx`、`.pdf`。

研究默认保留 20 次外部调用、900 秒、3 轮限制，最多纳入 12 篇候选；新增模型阶段同样计量，预算不足时本地保存阶段性报告。初始操作性门槛与适用边界见 [智能体流程](docs/04-agent-workflow.md)。PDF 使用随项目分发的 OFL 中文字体，不依赖在线转换；复杂表格与科研语义仍须人工核对。

人工质量评价支持指定本地标注文件，未知标签不当作零或正确结果：

```bash
.venv/bin/python -I scripts/evaluate_research.py tests/fixtures/evaluation_template.json
```

该文件只是全未知标签的人工模板，不是真实论文评测。真实资料、密钥和原始模型响应不提交到仓库。

# Paper Scout

本地单用户计算机领域文献调研原型：Python＋FastAPI、Vue 3＋TypeScript、SQLite 和显式状态机。**用户通过对话协作，状态机只负责后台执行；主界面不是任务工作流控制台。**

**当前是资料收集与阶段性报告原型，不是已经完成的自主科研分析系统。** 已实现可恢复的检索／文本读取流程和离线核心回归；尚未实现研究字段的语义提取、跨论文可靠比较、主张支持核验与充分性判定。不能用“找到两篇论文”或模型自评分宣称科研任务完成。

## 当前实现与边界

| 项目 | 当前情况 |
| --- | --- |
| 交互 | 对话时间线、独立草稿、会话重命名、删除／撤销／独立回收站批量管理；过程、来源和报告按需查看 |
| 输入 | 自然语言提出问题、年份、关注维度和输出要求；模型澄清或形成经入口校验的范围，保留每次运行初始快照 |
| AI服务 | 按供应商保存协议、地址、单份密钥及多个模型；仅在对话输入区选择供应商与型号，真实兼容性未验收 |
| 无模型 | 首条或显式研究按原始问题简单检索；支持显式执行控制，不能理解任意补充或回答论文问题，原因与原消息可见 |
| 检索 | arXiv、年份范围、去重、查询／错误记录；候选相关性未可靠语义复核 |
| 文本 | 元数据、摘要与实际 PDF 页分别保存；扫描／空文本、失败、截断明确标记，无 OCR |
| 控制 | 串行执行、暂停、补充、同次继续、取消、任务／运行历史 |
| 来源 | 每运行元数据快照、追加式文本快照、精确字符位置与原文摘录；有效定位不等于主张获支持 |
| 输出 | 可核查文本存在时 `partial` 阶段性 Markdown；没有可核查文本时 `failed`，不生成假成功报告 |
| 尚未实现 | 语义字段提取、实验条件比较、可靠覆盖判断、Word／PDF 报告导出 |

默认运行限制：3轮、每轮最多3条查询、每条最多5条结果、最多3篇全文尝试、20次累计外部调用、900秒实际执行时间。PDF 每跳计数，最多25 MiB、50页、5次重定向、10秒解析时限。暂停等待不计执行时间，失败的实际请求仍计数；没有自动重试。token 缺失保持 `null`，不做金额预算。

这些是资源边界，不是质量保证。设计文档的6篇、60%等建议阈值没有被冒充成语义验收。

## 对话式使用

1. 在统一输入框描述调研目标，例如“检索多智能体通信方面近三年的工作，重点关注实验设置”。配置模型时，助手可澄清问题并将范围交给后台研究执行。
2. 执行中直接发送“只保留离散通信的方法”等补充；系统在安全检查点处理，不必先手动暂停和保存。能解释且研究仅为此消息临时暂停时，重新规划后继续同次运行。
3. 继续在同一会话追问资料。默认自动判断意图；不希望为回答另做检索时可选择“只问已有资料”，回答本身只使用已保存来源、不新建研究或查询；原本正在执行的研究可在临时检查点后继续。回答引用可打开实际来源快照、页码和原文区间，模型语义支持仍需复核。
4. 暂停／继续／停止作为辅助控制；人工暂停不会因为资料追问被自动解除。“停止”会中断当前对话并取消研究，尚未创建研究运行时也有效；迟到模型结果不会再启动研究，已发起调用仍计用量。阶段性结束后仍可对话，新检索创建新运行，旧报告与来源保留。
5. 消息处理失败时原文仍在历史中；不确定的发送可重试同一请求标识，不重复创建或执行。重启不自动重放已开始的模型请求。
6. 历史对话右侧菜单支持重命名和删除。重命名不修改研究问题；删除会停止当前工作并移到回收站，可撤销或从独立回收站恢复，恢复不自动重新执行。软删除保留消息、来源与用量；回收站另支持确认后彻底删除。

对话默认累计40次模型调用／900秒实际执行时间，单次不超过60秒或剩余时间；与研究 Run 的外部调用和执行预算分别显示。上下文为有界历史与已保存片段，不代表已读完所有论文。未配置模型时无法使用完整自然语言研究协作；详细规则见 [会话执行语义与用量](<docs/03-data-and-api.md#会话执行语义>)。

## 本地运行

仅支持一个后端进程／一套串行 worker；不要多个进程共享同一运行数据库。默认只在回环地址开发，不是带认证的多用户服务。

### 后端：在仓库根目录

首次安装使用 [依赖锁文件](<backend/requirements-lock.txt>)；已有环境不要重新创建覆盖。当前离线验证环境为 Python 3.9.6，未据此保证其他 Python 环境兼容；3.9 已结束上游维护，不适合生产部署。

```bash
# 仅首次创建环境
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt

# 核心状态、限制、来源和接口的定向回归；不调用真实外部服务
PYTHONPATH=. .venv/bin/python -m pytest tests/test_storage.py tests/test_workflow_engine.py tests/test_api_tasks_and_runs.py tests/test_api_health.py -q

# 本地启动；运行中不要使用热重载中断任务
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

默认数据库保存在 Git 忽略的运行数据目录。已知旧 schema 进行增量迁移，不删除历史；进程启动把旧 `running/pause_requested` 标为 `interrupted`，不自动重放可能产生费用的调用。旧记录缺少的完整初始范围不能凭现有任务反推伪造。

### 前端：在 `frontend/` 执行

```bash
npm ci
npm run build
npm run dev
```

开发页面为 `http://127.0.0.1:5173`，`/api` 代理到后端8000端口；端口被占用时明确失败，不偷偷切换端口。脚本显式使用 TypeScript Vite 配置，避免生成的 JavaScript 配置遮蔽它。生产构建成功不等于生产部署已完成；`npm run preview` 没有完整生产 API 部署方案。

### 界面与主题

侧栏保留会话历史、回收站和设置，首页以输入框为中心。外观采用中性黑白灰，提供亮色、暗色和跟随系统三种模式，默认跟随系统并实时响应系统切换。在“设置 → 外观”选择后即时生效，无需保存模型配置；选择仅保存在当前浏览器，不发送给后端。浏览器不允许保存时仍可在当前页面切换，并明确提示不会持久保留。

设置按通用、AI服务、外观、数据管理、研究与用量分组。通用可选 Enter 或 Ctrl / ⌘ + Enter 发送、默认消息模式和是否自动跟随最新消息；向上阅读历史时不会强制跳到底部，输入法组词不会触发发送。外观可调对话字号与阅读宽度。除模型配置需提交保存外，界面偏好即时生效并自动保存在当前浏览器。

设置不显示统一底栏或“完成”按钮，使用右上角关闭、Esc 或空白遮罩退出；模型保存和取消放在编辑表单内。

回收站从侧栏或设置的数据管理进入独立窗口，提供搜索、删除时间／名称排序、分页、多选恢复与彻底删除、全部恢复和清空。选择只作用于当前页，切换搜索、排序或页码后清除选择；全部恢复与清空作用于整个回收站，确认文字会显示总数。彻底删除移除该会话的消息、研究记录、用量和报告，保留其他运行仍在使用的论文与来源；目标会话的在途请求结束前不能彻底删除。没有自动过期清理。

数据管理可导出当前已加载对话的 Markdown 或 JSON、进入回收站、确认后恢复默认界面偏好。导出包含消息与引用摘录，JSON 另含运行信息和用量；不包含论文全文、阶段性报告文件、模型配置、密钥或未发送草稿，也不支持作为完整备份导入。运行中的对话导出为当时的快照，研究报告仍从资料区单独下载。恢复默认只重置界面选项，不清除会话或模型。

### AI服务

在“设置 → AI服务”添加供应商：填写供应商名称（可选，留空使用地址主机名）、接口类型、API 根地址和所需 API Key，再获取并多选可用模型。也可以在下拉框输入模型 ID 手动添加。同一家供应商只有一套地址、协议和凭据，多个型号保存在其模型清单中。

设置仅负责配置和删除供应商。新增、更新或获取模型都不会选用型号，也没有“使用”按钮；保存后，在对话输入区的模型菜单按供应商分组选择具体型号。尚未选择时会提示先选模型，有供应商但无当前型号时不能直接发送。一次只使用一个型号，不做并行或自动路由。移除正在使用的型号或删除其供应商后，需要在对话中重新选择，不自动切到其他型号。

“获取模型”由本机后端请求该地址下的 `/models`。OpenAI 两种协议使用其模型列表格式；Anthropic 使用对应鉴权与游标分页，支持“加载更多”。HTTP请求各阶段超时15秒、不自动重试、不跟随重定向；不会发送对话内容或发起生成调用。列表返回不证明所选型号支持当前生成协议；服务未提供列表或返回错误时明确提示，可手动添加 ID。

配置保存在服务端 `DATA_DIR/model-settings.json`，文件权限600。浏览器不持久保存密钥，读取接口只返回是否已保存；编辑时密钥留空保留本供应商原密钥，新供应商不继承其他凭据。更改地址需重新输入或明确清除原密钥。

旧单模型及多档案文件读取时迁移为供应商结构：只有地址、协议与密钥均相同的旧档案才合并，型号去重，原来的当前型号保留；不同密钥保持独立。读取不改写原文件，下一次保存才原子写入新结构。文件内为服务端明文密钥，不得提交或公开。

有排队、执行中或仍未结束的外部请求时，不能切换模型、修改或删除当前供应商；其他供应商可配置。保存不调用模型，不代表连通性已验证。设置窗口可随时关闭，已提交的保存继续，结果在对话页反馈。界面不会返回已保存的密钥。

研究与用量分为“用量概览”和“执行上限”：前者展示当前已加载对话的模型调用、耗时、剩余额度与 Token，并可切换查看每次调研的调用、轮次、状态、Token 和终止原因；后者只读展示服务端提供的执行上限。各记录使用自身保存的上限，缺失 Token 保持未知，不估算费用。

本机保存的模型设置优先于环境变量与 `.env`，没有当前模型的状态也会在重启后保持。尚未保存界面配置时使用以下环境配置：

参考 [配置模板](<.env.example>)，仅在没有本地配置时复制为仓库根目录的 `.env`，不要覆盖已有配置、提交或公开密钥。

- `LLM_PROTOCOL`：`openai_chat`、`openai_responses` 或 `anthropic_messages`。
- `LLM_BASE_URL`：API 前缀，如供应商要求的 `/v1`，不是具体 endpoint。
- `LLM_MODEL`：用户实际选择的型号，不预填未经确认的型号。
- `LLM_API_KEY`：按供应商要求设置。配置不全时启动明确失败；密钥不回显。
- 模型三个配置全部为空：使用明确披露的无模型模式，不能自动理解补充。要解释补充，可通过设置界面选择当前模型后继续暂停／等待补充的运行；只修改环境配置时需重启后端。

研究问题、补充与候选摘要可能发送给所选云服务并产生用量。真实调用前核验能力、费用和数据处理政策；离线验证不证明真实模型、搜索或 PDF 网络链路可用。

## 接口概览

- `GET /api/settings`：读取脱敏AI服务配置；`/settings/providers` 管理供应商，`/settings/models` 获取模型列表，`/settings/selection` 在对话中选择供应商与型号。已发布的 `POST /settings` 单模型入口仍更新当前供应商。
- `/api/conversations/{task_id}/rename`、`/trash`、`/restore`：重命名、移到回收站和恢复；`GET /api/conversations?deleted=true` 查看回收站。
- `/api/conversations/trash`：回收站搜索、排序及分页；`/trash/restore`、`/trash/delete`：批量或全量恢复、彻底删除。
- 会话创建、列表、详情与消息追加；默认自然语言自动意图，HTTP只排队。
- 会话消息包含真实处理状态、所属运行、来源引用及错误；消息发送有请求标识，重发不重复执行。
- 任务创建、列表、详情、任务的运行历史（既有接口保留）。
- 创建运行：`202`；活动运行冲突：`409`。
- 运行状态、暂停／继续／取消、补充信息、事件、候选论文。
- `/api/runs/{run_id}/papers/{paper_id}` 返回本次论文、实际来源快照与证据定位。
- `/api/runs/{run_id}/report` 和 `/report.md`；已有运行暂无报告为 `409`，运行不存在为 `404`。

既有运行补充接口只允许在 `paused/needs_input`；新的会话消息入口允许执行中发送，并在检查点安全衔接。终态不能继续或再次暂停，但会话仍可追问资料或发起新研究。新研究创建新运行，旧历史保留。

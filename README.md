# Paper Scout

本地单用户计算机领域文献调研原型：Python＋FastAPI、Vue 3＋TypeScript、SQLite 和显式状态机。

**当前是资料收集与阶段性报告原型，不是已经完成的自主科研分析系统。** 已实现可恢复的检索／文本读取流程和离线核心回归；尚未实现研究字段的语义提取、跨论文可靠比较、主张支持核验与充分性判定。不能用“找到两篇论文”或模型自评分宣称科研任务完成。

## 当前实现与边界

| 项目 | 当前情况 |
| --- | --- |
| 输入 | 问题、年份、关注维度；入口校验，保留每次运行的初始范围 |
| 模型 | 三种协议适配器；配置后用于结构化检索规划，真实供应商兼容性未验收 |
| 无模型 | 明确标记的原始问题检索；复杂中文问题效果未保证，补充不被静默忽略 |
| 检索 | arXiv、年份范围、去重、查询／错误记录；候选相关性未可靠语义复核 |
| 文本 | 元数据、摘要与实际 PDF 页分别保存；扫描／空文本、失败、截断明确标记，无 OCR |
| 控制 | 串行执行、暂停、补充、同次继续、取消、任务／运行历史 |
| 来源 | 每运行元数据快照、追加式文本快照、精确字符位置与原文摘录；有效定位不等于主张获支持 |
| 输出 | 可核查文本存在时 `partial` 阶段性 Markdown；没有可核查文本时 `failed`，不生成假成功报告 |
| 尚未实现 | 语义字段提取、实验条件比较、可靠覆盖判断、Word／PDF 报告导出 |

默认运行限制：3轮、每轮最多3条查询、每条最多5条结果、最多3篇全文尝试、20次累计外部调用、900秒实际执行时间。PDF 每跳计数，最多25 MiB、50页、5次重定向、10秒解析时限。暂停等待不计执行时间，失败的实际请求仍计数；没有自动重试。token 缺失保持 `null`，不做金额预算。

这些是资源边界，不是质量保证。设计文档的6篇、60%等建议阈值没有被冒充成语义验收。

## 本地运行

仅支持一个后端进程／一套串行 worker；不要多个进程共享同一运行数据库。默认只在回环地址开发，不是带认证的多用户服务。

### 后端：在仓库根目录

首次安装使用 [依赖锁文件](<backend/requirements-lock.txt>)；已有环境不要重新创建覆盖。当前离线验证环境为 Python 3.9.6，未据此保证其他 Python 环境兼容；3.9 已结束上游维护，不适合生产部署。

```bash
# 仅首次创建环境
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt

# 核心状态、限制、来源和接口的定向回归；不调用真实外部服务
PYTHONPATH=. .venv/bin/python -m pytest tests/test_storage.py tests/test_workflow_engine.py tests/test_api_tasks_and_runs.py tests/test_api_health.py -q

# 本地启动；运行中不要使用热重载中断任务
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

默认数据库保存在 Git 忽略的运行数据目录。已知旧 schema 进行增量迁移，不删除历史；进程启动把旧 `running/pause_requested` 标为 `interrupted`，不自动重放可能产生费用的调用。旧记录缺少的完整初始范围不能凭现有任务反推伪造。

### 前端：在 `frontend/` 执行

```bash
npm ci
npm run build
npm run dev
```

开发页面为 `http://127.0.0.1:5173`，`/api` 代理到后端8000端口；端口被占用时明确失败，不偷偷切换端口。脚本显式使用 TypeScript Vite 配置，避免生成的 JavaScript 配置遮蔽它。生产构建成功不等于生产部署已完成；`npm run preview` 没有完整生产 API 部署方案。

### 可选模型配置

参考 [配置模板](<.env.example>)，仅在没有本地配置时复制为仓库根目录的 `.env`，不要覆盖已有配置、提交或公开密钥。

- `LLM_PROTOCOL`：`openai_chat`、`openai_responses` 或 `anthropic_messages`。
- `LLM_BASE_URL`：API 前缀，如供应商要求的 `/v1`，不是具体 endpoint。
- `LLM_MODEL`：用户实际选择的型号，不预填未经确认的型号。
- `LLM_API_KEY`：按供应商要求设置。配置不全时启动明确失败；密钥不回显。
- 模型三个配置全部为空：使用明确披露的无模型模式，不能自动理解补充。要解释补充，配置模型并重启后端，再继续暂停／等待补充的运行。

研究问题、补充与候选摘要可能发送给所选云服务并产生用量。真实调用前核验能力、费用和数据处理政策；本次修复未调用付费模型、未实测真实搜索／PDF 网络链路。

## 接口概览

- 任务创建、列表、详情、任务的运行历史。
- 创建运行：`202`；活动运行冲突：`409`。
- 运行状态、暂停／继续／取消、补充信息、事件、候选论文。
- `/api/runs/{run_id}/papers/{paper_id}` 返回本次论文、实际来源快照与证据定位。
- `/api/runs/{run_id}/report` 和 `/report.md`；已有运行暂无报告为 `409`，运行不存在为 `404`。

补充只允许在 `paused/needs_input`；终态不能继续或再次暂停。停止或取消后可以为同一任务新建运行，旧历史保留。
